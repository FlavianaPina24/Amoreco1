Grupo: Validação de Documentos (DocumentValidationTests.feature)

# Cenário Método Finalidade Steps
1/22 Validar CNPJ com caracteres alfanuméricos POST Consulta (Validação) - Verifica se o serviço aceita um CNPJ com formato alfanumérico válido.
  1. Given: um documento Z7NNC4PE/9520-06 é preparado.
  2. When: uma requisição de validação POST é enviada.
  3. Then: a resposta deve ser 200 OK com a mensagem "Documento com formato válido".
2/22 Validar CNPJ com menos de 14 dígitos POST Consulta (Validação) - Garante que o serviço rejeita CNPJs com tamanho incorreto (menor).

  2. When: uma requisição de validação POST é enviada.
  3. Then: a resposta deve ser 400 Bad Request com a mensagem "CNPJ inválido: quantidade de dígitos incorreta".

  3. Then: a resposta deve ser 400 Bad Request com a mensagem "CNPJ inválido: quantidade de dígitos incorreta".
4/22 Validar CNPJ com caracteres não alfanuméricos POST Consulta (Validação) - Garante que o serviço rejeita CNPJs que contêm caracteres especiais inválidos.

Grupo: Fluxos de Negócio Principais (MainBusinessFlows.feature)

# Cenário Método Finalidade Steps
11/22 Criação de um novo cliente válido POST Criação - Testa o fluxo básico de criação de um novo cliente com dados estáticos.
  1. Given: o sistema está configurado para a ação CRIAR_CLIENTE.
  2. When: uma requisição POST é enviada para /v1/clientes com a chave NOVO_CLIENTE_VALIDO.
  3. Then: a resposta deve ser 201 Created com a mensagem "Cliente criado com sucesso".
12/22 Busca de um cliente existente GET Consulta - Testa a busca de um cliente pré-existente (id=1) pelo seu ID.
  1. Given: o sistema está configurado para a ação BUSCAR_CLIENTE.
  2. When: uma requisição GET é enviada para /v1/clientes/1.
  3. Then: a resposta deve ser 200 OK e o corpo deve conter o nome "João Silva".
13/22 Alteração de um cliente existente PUT Alteração - Testa a atualização de um cliente pré-existente.
  1. Given: o sistema está configurado para a ação ALTERAR_CLIENTE.
  2. When: uma requisição PUT é enviada para /v1/clientes/1 com a chave ATUALIZACAO_NOME_VALIDA.
  3. Then: a resposta deve ser 200 OK com a mensagem "Cliente atualizado".
14/22 Deleção de um cliente existente DELETE Delete - Testa a exclusão de um cliente pré-existente.
  1. Given: o sistema está configurado para a ação DELETAR_CLIENTE.
  2. When: uma requisição DELETE é enviada para /v1/clientes/1.
  3. Then: a resposta deve ser 204 No Content.
15/22 Busca de um cliente que foi deletado GET Consulta (Validação de Erro) - Garante que um cliente, após ser deletado, não pode mais ser encontrado.
  1. Given: o sistema está configurado para a ação BUSCAR_DELETADO.
  2. When: uma requisição GET é enviada para /v1/clientes/1.
  3. Then: a resposta deve ser 404 Not Found com a mensagem "Cliente não encontrado".
16/22 Criação de cliente com CPF preenchido com zeros POST Criação (Geração de Massa) - Testa a "Fábrica de Dados", validando a regra de completar um CPF com zeros à esquerda.
  1. Given: o sistema está configurado para a ação CRIAR_CLIENTE.
  2. When: uma requisição POST é enviada para /v1/clientes com a chave CPF_9_DIGITOS e a regra COMPLETAR_CPF_COM_ZEROS.
  3. Then: a resposta deve ser 201 Created.
17/22 Criação de cliente com CNPJ numérico preenchido com zeros POST Criação (Geração de Massa) - Testa a "Fábrica de Dados", validando a regra de completar um CNPJ numérico com zeros à esquerda.

  3. Then: a resposta deve ser 201 Created.
18/22 Criação de cliente com CNPJ Alfanumérico preenchido com zeros POST Criação (Geração de Massa) - Testa a "Fábrica de Dados", validando a regra de completar um CNPJ alfanumérico com zeros à esquerda.

19/22 Busca de cliente criado com CPF preenchido com zeros GET Consulta (Ponta a Ponta) - Valida que um cliente criado com CPF gerado pode ser buscado.
