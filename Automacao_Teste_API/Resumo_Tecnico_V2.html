Resumo Técnico do Projeto de Automação de API V2

Visão Geral do Projeto

Este documento detalha a arquitetura final da plataforma de automação de testes de API, uma solução robusta, escalável e de nível empresarial. O projeto evoluiu de uma simples automação para um ecossistema de testes completo, com uma fonte de dados centralizada na nuvem, mocks de serviços inteligentes e uma clara separação entre comportamento e dados.

Componentes Principais

Fonte de Dados
MongoDB Atlas (Nuvem)

É a nossa **fonte única da verdade**. Todos os dados e "moldes" de cenários de teste são armazenados em uma coleção centralizada, permitindo gestão e escalabilidade massivas sem alterar o código.

Painel de Controle
Arquivos .feature

Atuam como um painel de controle legível e de alto nível. Eles descrevem o **comportamento** esperado e apontam (via chave_cenario) para os dados no MongoDB, mas não contêm mais nenhum dado "amarrado".

Motor de Teste
Java / Cucumber / REST Assured

O coração da plataforma. As classes de Step Definition orquestram todo o fluxo: buscam os dados no Mongo, aplicam regras de negócio, montam as requisições com REST Assured e validam as respostas dos Mocks.

Nossas Vitórias (Módulos Implementados)

✅ Projeto 4: O "Banco de Dados Universal"

A realização da nossa visão de arquitetura pura. Migramos **TODA** a massa de teste do projeto para o MongoDB, eliminando completamente os dados "amarrados" nos arquivos .feature. O projeto agora é mais leve, robusto e profissional.

✅ Projeto 3: A "Fundação de Dados Persistente"

A revolução do nosso projeto. Substituímos a gestão de dados volátil por uma conexão direta com um banco de dados MongoDB Atlas na nuvem, adotando uma arquitetura de nível empresarial.

✅ Projeto 2: A "Fábrica de Dados"

Implementamos um sistema de regra_massa que permite a geração e transformação dinâmica de dados. O motor busca um "molde" no MongoDB e aplica regras sobre ele (ex: completar um CPF com zeros) antes de enviar a requisição.

✅ Projeto 1: O "Módulo de Inteligência"

Fomos além do teste de API tradicional. Criamos uma classe de lógica de negócio pura (ValidadorDocumento.java) para validar regras complexas, como o cálculo de dígitos verificadores, garantindo que nossos testes validam a integridade e a lógica real do negócio.

Suíte de Testes Atual

A plataforma atualmente executa um total de **30 cenários** de teste, divididos em 3 grandes grupos:

  • Testes de API (Real): 8 cenários que validam a integração com a API pública jsonplaceholder.typicode.com.
  • Testes de Validação de Documento (Local): 10 cenários que testam o nosso "Módulo de Inteligência" contra diversas regras de CPF e CNPJ.
  • Testes de Fluxo de Negócio (Local): 12 cenários que simulam o ciclo de vida completo de um cliente (Criação, Busca, Alteração, Deleção) em nosso ambiente mockado.

Próximos Passos

💡 Projeto 5: A "Torre de Controle"

O próximo grande salto quântico. A missão é unificar todos os nossos servidores de mock em um único "Super Mock". Isso nos permitirá criar cenários de teste de integração entre os nossos próprios serviços simulados, respondendo a perguntas como: "Ao chamar a API de CRIAR_CLIENTE, ela, por baixo dos panos, chama corretamente a API de VALIDAR_DOCUMENTO?".
